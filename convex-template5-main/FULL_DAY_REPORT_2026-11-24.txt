2.4 SEC-01 Multi-Workspace RBAC Remediation & Architecture
----------------------------------------------------------------------------------------------------
- Identified Critical Vulnerability:
  * File: `apps/app/src/app/[locale]/(admin)/layout.tsx`
  * Vulnerability: `workspaces.some(w => w.role === "admin" || w.role === "owner")` permitted cross-tenant
    privilege leakage. If user held Admin in Workspace B and Member in Workspace A, they could access
    Workspace A's Admin routes.
- Technical Fix Applied:
  * Extracted trusted active workspace ID from HTTP-only / SameSite cookies (`ws` or `indiapay_active_ws`).
  * Matched cookie explicitly against authenticated user's memberships returned by `api.orgs.myWorkspaces`.
  * If cookie missing, safely fell back to primary workspace (`workspaces[0]`).
  * Enforced: `activeWorkspace.role === "admin" || activeWorkspace.role === "owner"`.
  * Enforced: `activeWorkspace.status !== "suspended"`.
  * Blocked unauthorized or suspended users with safe redirect to `/`.
  * Cleaned up all `any` types with explicit `WorkspaceMembership` interface.

3.1 SEC-01 Multi-Workspace Authorization Guard & Cookie Resolution
----------------------------------------------------------------------------------------------------
File: `apps/app/src/app/[locale]/(admin)/layout.tsx`

```typescript
// Strongly-typed membership contract eliminating 'any'
interface WorkspaceMembership {
  _id: string;
  name: string;
  role: string;
  status?: "active" | "suspended" | "pending";
}

const workspaces = (await fetchQuery(
  api.orgs.myWorkspaces,
  {},
  { token },
)) as WorkspaceMembership[];

if (!workspaces || workspaces.length === 0) {
  return redirect("/");
}

// 1. Resolve active workspace from server cookie
const cookieStore = await cookies();
const activeWsCookie =
  cookieStore.get("ws")?.value ||
  cookieStore.get("indiapay_active_ws")?.value;

// 2. Exact workspace match
let activeWorkspace = workspaces.find((w) => w._id === activeWsCookie);
if (!activeWorkspace) {
  activeWorkspace = workspaces[0];
}

// 3. Status and Role verification on exact active workspace
const isSuspended = activeWorkspace.status === "suspended";
const activeRole = activeWorkspace.role;
const isAuthorized = !isSuspended && (activeRole === "admin" || activeRole === "owner");

if (!isAuthorized) {
  return redirect("/");
}
```

3.2 Cross-Tenant IDOR Protection on Sensitive Queries & Mutations
----------------------------------------------------------------------------------------------------
All sensitive queries and mutations in Convex now mandate workspace ownership verification:
- `requireMember(ctx, userId, workspaceId)`: Confirms user has an active membership record in the target
  workspace.
- `requireRole(ctx, userId, workspaceId, allowedRoles)`: Confirms user's role in that specific workspace
  matches allowed roles (`admin` | `owner`). Suspended memberships throw `Forbidden` immediately.
